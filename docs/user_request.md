## 2. 개발 흐름 변경 (R1, R2) — 단계 0에서 반영함

- ux-designer는 사용자가 요청할 때만 부른다. 피드백이 나오면 요약만 하고 멈추며, 사용자가 반영할 항목을 고른 뒤에 작업한다.
- 스크린샷은 ux-designer를 부를 때만 찍는다. 화면 문구가 바뀌면 시나리오만 함께 고친다.
- 절차를 가볍게 했다(사용자 합의, 2026-10-13).
  - logger를 없앴다. 커밋은 메인 세션이 한다. `docs/DEVLOG.md`도 더 쓰지 않는다.
  - reviewer는 위험한 변경에만 쓴다: 서버 API, DB, 날짜·상태 계산, 동기화, 알림, 보안.
  - 작은 수정은 서브에이전트 없이 바로 한다.
- PRD 원본은 `docs/PRD.md` 하나로 정했다.
- 자세한 규칙은 `CLAUDE.md`의 "개발 흐름"에 있다.

## 3. 화면 구조 (R3, R5)

### 시작 화면 (R3)
- 앱을 열면 시작 화면이 나온다.
- 큰 버튼 2개를 둔다: **오늘의 할 일 보기**(→ 대시보드), **히스토리 보기**(→ 달력).
- PRD 목표 "앱을 열면 3초 안에 오늘 할 일을 안다"와 부딪치지 않도록, 시작 화면에도 한 줄 요약을 보여 준다(예: "오늘 할 일 3개 (밀린 일 2개 포함)"). 버튼을 누르지 않아도 오늘 상태를 알 수 있다.
- 대시보드와 히스토리 화면 위쪽에는 시작 화면으로 돌아가는 버튼을 둔다. Android 뒤로 가기 버튼도 이 흐름을 따른다.
- 화면이 4개(시작·대시보드·히스토리·팝업)로 늘어나므로 화면 이동은 URL 해시로 관리한다(`#/`, `#/today`, `#/history`). 새 라이브러리는 넣지 않는다. 이렇게 하면 뒤로 가기와 PWA 바로가기가 자연스럽게 동작한다.

### 추가·편집 팝업 (R5)
- "+"를 누르면 지금 화면 위로 바텀 시트(아래에서 올라오는 팝업)가 열린다. 대시보드는 뒤에 흐리게 보인다.
- 카드를 눌러 여는 편집도 같은 시트를 쓴다. 추가와 편집이 같은 모양이어야 덜 헷갈린다.
- 시트를 닫는 방법은 바깥 영역 탭, 아래로 끌기, 뒤로 가기다. 입력한 내용이 있으면 "작성 중인 내용을 버릴까요?"를 묻는다(지금 동작 유지).
- 데스크톱에서는 화면 가운데 대화 상자로 보인다.

## 4. 집안일 추가 경험 (R6, R7)

### 기본 집안일 목록 (R6)
- 시트를 열면 먼저 **기본 집안일 목록**이 칩(버튼) 형태로 나온다. 하나를 누르면 이름, 아이콘, 추천 주기가 채워진다.
- 초안 (약 20개, 분류별):

| 분류 | 집안일 (아이콘 · 추천 주기) |
| --- | --- |
| 주방 | 설거지 🍽️ 1일 · 냉장고 정리 🧊 14일 · 냉장고 청소 🧽 30일 · 가스레인지 청소 🔥 14일 · 전자레인지 청소 📦 30일 |
| 청소 | 청소기 🧹 3일 · 걸레질 🧼 7일 · 욕실 청소 🛁 7일 · 변기 청소 🚽 7일 · 창틀 먼지 🪟 30일 · 에어컨 필터 ❄️ 90일 |
| 세탁 | 빨래 👕 3일 · 수건 교체 🧺 3일 · 이불 빨래 🛏️ 14일 · 베개 커버 교체 🛌 7일 |
| 생활 | 분리수거 ♻️ 3일 · 음식물 쓰레기 🗑️ 2일 · 화분 물주기 🪴 7일 · 장보기 🛒 7일 · 공과금 확인 💳 30일 |

- 기본 목록은 앱에 고정한다(`shared/presets.json`). 이미 등록한 집안일은 목록에서 "추가됨"으로 흐리게 표시한다.
- 목록에 없는 일은 "직접 입력"으로 이름을 쓴다. 등록한 뒤에는 이름, 아이콘, 주기를 모두 편집할 수 있다.
- **마지막 수행일 입력을 짧게**: 날짜 선택기 대신 "오늘 / 어제 / 3일 전 / 일주일 전 / 날짜 선택" 칩으로 고른다. 기본값은 오늘이다.
- **주기 입력을 짧게**: "매일 / 3일 / 1주 / 2주 / 한 달 / 직접 입력" 칩으로 고른다.

### 아이콘 추천 (R6)
- 이름을 입력하면 아이콘 칸이 자동으로 채워진다. 사용자가 다른 이모지로 바꿀 수 있다. 바로 고를 수 있도록 추천 후보 5개 정도를 칩으로 함께 보여 준다.
- 추천 방식 후보:
  - (A) **키워드 사전**: 앱 안에 "빨래→👕, 쓰레기→🗑️" 같은 단어와 이모지 표를 둔다. 비용이 없고, 오프라인에서도 바로 동작한다. 표에 없는 단어는 🧹로 채운다.
  - (B) **AI 추천**: PC 서버가 Claude API(Haiku 모델)에 이름을 보내 이모지를 받는다. 어떤 이름에도 그럴듯한 아이콘을 주지만 API 키와 인터넷이 필요하고 요청마다 아주 적은 비용이 든다. 집 밖(오프라인)에서는 동작하지 않는다.
  - **권장: A를 기본으로 하고, 사전에 없는 단어만 B로 보완한다.** 키를 설정하지 않으면 A만 쓴다.
- MCP는 Claude Code 같은 AI 에이전트가 도구를 쓰는 방식이라 앱 실행 중 기능으로는 맞지 않는다. 그래서 후보에서 뺐다.

### 일회성 할 일 (R7)
- 시트 위쪽에서 **반복 / 한 번만**을 고른다.
- 한 번만인 할 일에는 이름, 아이콘, **마감일**(기본 오늘)을 입력한다. 메모는 선택이다.
- 표시 규칙:
  - 배지는 반복 일과 같은 규칙(D-n / D-Day / D+n)이고, 마감일을 기준으로 계산한다.
  - 게이지는 등록일부터 마감일까지를 100%로 잡는다.
  - 카드에 "한 번" 표시를 작게 붙인다.
- 완료하면 목록에서 사라지고 히스토리에만 남는다. 실행 취소로 되살릴 수 있다.
- 데이터: `Chore`에 `kind`(`recurring` | `once`)와 `dueOn`(일회성의 마감일)을 추가한다. 반복 일의 계산 규칙은 바뀌지 않는다.

## 5. 완료 기록과 히스토리 (R4)

R4는 완료 체크(F3)가 있어야 시작할 수 있다. F3을 먼저 하고, 이번 계획에 U6 피드백도 함께 넣는다.

### 완료 체크 (F3)
- 카드의 체크 버튼을 한 번 누르면 완료다.
- 누르면 아래에 "○○ 완료 · 실행 취소"가 몇 초 동안 뜬다. 이 알림은 "+" 버튼과 겹치지 않는다(U6).
- 완료할 때 서버에 **완료 기록**을 남긴다:
  - `doneOn`: 완료한 날짜
  - `dueOn`: 그때의 예정일 (새로 추가하는 필드)
- 이 두 값으로 제때 했는지(`doneOn ≤ dueOn`)와 며칠 늦었는지를 나중에 다시 계산할 수 있다.
- 반복 일은 마지막 수행일이 완료 기록 중 가장 늦은 날짜로 바뀐다(PRD 7장 규칙). 실행 취소하면 그 기록을 지우고 원래 상태로 돌아간다.

### 히스토리 화면
- **달력**: 한 달 단위로 보고, 좌우로 넘겨 다른 달로 간다.
- **날짜 칸 표시**:
  - 그날 완료한 일의 수를 점이나 숫자로 보여 준다.
  - 칸 색으로 그날의 상태를 나눈다:
    - **깔끔한 날**(초록): 그날 밀린 일이 하나도 없었다.
    - **밀린 일이 있던 날**(주황): 예정일을 넘긴 일이 하나 이상 있었다.
    - **기록 없음**(회색): 집안일을 등록하기 전이다.
  - "그날 밀려 있었는지"는 완료 기록의 `dueOn`과 `doneOn`으로 계산한다. 예정일 다음 날부터 완료한 날 전날까지가 밀린 기간이다. 아직 완료하지 않은 지연은 오늘까지 밀린 것으로 본다.
- **날짜를 누르면**: 아래에 그날 완료한 일 목록이 나온다. 아이콘, 이름, "제때" 또는 "2일 늦게"가 함께 보인다.
- **꾸준함 지표** (달력 위):
  - 이번 달 제때 완료율 (예: 18건 중 15건 제때)
  - 연속 깔끔한 날 (현재 n일 / 최장 m일)
- **한계**:
  - 마지막 수행일을 손으로 고치거나 주기를 바꾸면, 그 이전 기록의 계산이 조금 어긋날 수 있다.
  - 이번 기능 이전에 등록한 집안일은 완료 기록이 없다. 그래서 히스토리는 F3 이후부터 쌓인다.

## 6. UI 디자인 정비 (R8)

- 색, 글꼴 크기, 간격, 모서리, 그림자를 디자인 토큰(CSS 변수)으로 정리하고, 모든 화면이 이 토큰을 쓰게 한다.
- 방향 (기본안):
  - 밝은 회색 바탕에 흰 카드
  - 부드러운 그림자와 큰 모서리(16px)
  - 상태 색은 채도를 낮춰 차분하게
  - 숫자와 배지는 굵고 또렷하게
  - 시스템 다크 모드 지원
  - 글꼴은 Pretendard(한국어 가독성). 오프라인을 위해 웹 폰트는 앱에 포함한다.
- 지난 UX 피드백에서 정한 것은 유지한다:
  - 지연 상태는 "!", 왼쪽 띠, 빗금 게이지로 표시한다.
  - 터치 영역은 44px 이상이다.
  - 한국어 줄바꿈은 단어 단위다.
- 새 화면(시작, 시트, 히스토리)은 처음부터 이 토큰으로 만들고, 대시보드와 카드는 같은 단계에서 다시 칠한다.
- 결과는 사용자가 원할 때 ux-designer 리뷰로 확인한다(R1).

- 단계 3에서 일회성 할 일이 들어오면 상태 계산 규칙이 바뀐다. `choreStatus.ts`, `status.py`, `shared/status-cases.json`을 같이 고친다.
- 단계 1과 3에서 DB 테이블에 열이 추가된다. 지금 DB는 개발용 샘플뿐이다. 그래서 마이그레이션 도구 없이, 서버가 시작할 때 열이 없으면 추가하는 간단한 점검으로 처리한다.
- 폰 접속에 대해: 서비스 워커와 웹 푸시는 HTTPS에서만 동작한다. 하지만 화면을 보고 체크하는 데는 HTTP(`http://<PC IP>:5173`)로도 충분하다. 그래서 단계 1에서는 HTTP로 접속하고, HTTPS(mkcert)는 F7·F8을 할 때 다룬다.

| B1 | 아이콘 추가 기능에 오류가 있다 **(보류, 2026-10-15 사용자 결정)** | 재현 정보가 아직 없다. 아이콘을 입력하는 곳은 세 군데다: 집안일 추가·편집 폼, 프리셋 "+ 항목 추가" 폼, "+ 카테고리 추가" 폼(이모지). 웹은 아이콘을 코드 포인트 16자 이하로 검사하고, 서버 프리셋도 같은 상한을 둔다. Android 이모지 키보드 입력이나 길이 검사, 빈 값 처리 중 하나일 가능성이 있다. | 아래 "필요한 정보"를 받아 재현한 뒤 고친다. 세 입력 칸의 검사와 기본값 규칙을 하나로 맞춘다. |
