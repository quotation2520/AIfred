# AIFred PRD

> 2026-10-13부터 이 파일이 PRD 원본이다. Claude Docs의 "AIFred PRD 초안"은 2026-10-12 시점의 초안으로 남기고 더 갱신하지 않는다.

## 1. 개요

AIFred는 주기적으로 반복되는 집안일을 등록해 두면, 마지막 수행일 기준 경과 상태를 게이지로 보여주고 오늘 할 일과 밀린 일을 알려주는 개인용 집안일 대시보드다.

**문제**: 화분 물주기, 냉장고 청소, 걸레질처럼 주기가 서로 다른 집안일은 "마지막으로 언제 했는지"를 기억하기 어렵다. 그래서 너무 자주 하거나, 잊어버리고 한참 지나서야 알아챈다.

**목표**

- 앱을 열면 3초 안에 "오늘 무엇을 해야 하는지"를 알 수 있다.
- 각 집안일의 진행 상태(얼마나 남았는지, 얼마나 밀렸는지)를 게이지로 한눈에 본다.
- 완료 체크는 한 번의 탭으로 끝난다.

## 2. 대상 사용자와 시나리오

대상은 혼자 집안일을 관리하는 개인 1명(본인)이다. MVP는 단일 사용자 기준이며, 가족 공유는 향후 과제로 둔다.

1. **아침 확인**: 앱을 열면 "오늘 할 일" 목록과 빨간 D+n 경고가 맨 위에 보인다.
2. **완료 체크**: 화분에 물을 준 뒤 해당 카드의 체크 버튼을 누른다. 게이지가 다시 가득 찬다.
3. **새 집안일 추가**: "이불 빨래, 14일마다"를 입력해 등록한다. 마지막 수행일을 직접 지정할 수 있다.
4. **주기 조정**: 냉장고 청소를 30일에서 45일 주기로 바꾼다.

## 3. 핵심 기능 요구사항

MVP는 필수(P0) 기능 7개와 있으면 좋은(P1) 기능 1개로 구성된다.

| ID | 기능 | 요구사항 | 우선순위 |
| --- | --- | --- | --- |
| F1 | 집안일 등록/편집/삭제 | 이름, 주기(일 단위), 마지막 수행일(기본값: 오늘)을 입력한다. 아이콘/메모는 선택. | P0 |
| F2 | 대시보드 게이지 | 집안일마다 남은 기간을 게이지 바로 표시한다. 완료 직후 100%, 예정일에 0%. | P0 |
| F3 | 완료 체크 | 체크 한 번으로 마지막 수행일을 오늘로 갱신하고 게이지를 다시 채운다. 실수 대비 실행 취소를 제공한다. | P0 |
| F4 | D+n 지연 경고 | 예정일을 넘기면 빨간색 "D+n" 배지를 표시하고 카드를 강조한다. | P0 |
| F5 | 오늘 할 일 | 예정일이 오늘이거나 지난 집안일을 대시보드 상단에 모아 보여준다. 밀린 일이 먼저 오도록 정렬한다. | P0 |
| F7 | 정기 알림 | 평일 18:00, 주말 10:00에 폰이 집 Wi-Fi에 있으면 오늘 할 일을 푸시 알림으로 보낸다. (7장) | P0 |
| F8 | 오프라인 사용과 동기화 | 집 밖에서도 앱을 열고 체크할 수 있다. 변경 내용은 집 Wi-Fi에 연결될 때 서버와 동기화한다. (7장) | P0 |
| F6 | 수행 이력 | 완료 기록을 날짜별로 저장하고 집안일 상세에서 보여준다. | P1 |

## 4. 게이지 및 상태 계산 규칙

모든 계산은 날짜(일) 단위이며, 기준은 마지막 수행일과 주기다.

- 경과일 = 오늘 − 마지막 수행일
- 예정일 = 마지막 수행일 + 주기 (일찍 완료해도 완료일 기준으로 다시 계산)
- 남은 일수 = 예정일 − 오늘
- 게이지(%) = max(0, 남은 일수 ÷ 주기) × 100

| 상태 | 조건 | 표시 | 색상 |
| --- | --- | --- | --- |
| 여유 | 남은 일수 ≥ 2 | D-n | 초록 |
| 곧 할 일 | 남은 일수 = 1 (예정일 하루 전) | D-1 | 주황 |
| 오늘 | 남은 일수 = 0 | D-Day | 주황(강조) |
| 지연 | 남은 일수 < 0 | D+n (n = 지난 일수) | 빨강 |

주기가 1일인 집안일은 완료 직후부터 D-1(곧 할 일)로 표시된다.

예: 화분 물주기(주기 7일)를 10월 5일에 했다면, 10월 12일에 D-Day이고 10월 14일에는 빨간 D+2가 된다.

## 5. 데이터 모델

저장 대상은 집안일(Chore), 완료 기록(Completion), 알림 대상 폰(Device)이다. 게이지와 상태는 저장하지 않고 매번 계산한다.

**Chore**

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | string | 고유 ID (UUID, 폰에서 오프라인으로 만들어도 충돌 없음) |
| name | string | 집안일 이름 (예: 화분 물주기) |
| intervalDays | number | 주기(일), 1 이상 |
| lastDoneAt | date | 마지막 수행일 |
| icon | string | 선택, 이모지 또는 아이콘 키 |
| note | string | 선택, 메모 |
| createdAt | datetime | 등록 시각 |
| updatedAt | datetime | 마지막 수정 시각 (동기화 충돌 판단용) |
| deletedAt | datetime | 선택, 삭제 표시 (동기화로 삭제를 전달하기 위함) |

**Completion**

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | string | 고유 ID (UUID, 폰에서 생성 → 중복 업로드 방지) |
| choreId | string | 대상 집안일 |
| doneAt | datetime | 완료 시각 |

**Device** (알림 대상 폰)

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | string | 고유 ID |
| localIp | string | 공유기에서 예약한 폰의 고정 IP |
| pushSubscription | json | 웹 푸시 구독 정보 |
| lastSyncAt | datetime | 마지막 동기화 시각 |
| lastNotifiedOn | date | 마지막 알림 날짜 (하루 1회 제한용) |

## 6. 화면 구성

MVP는 대시보드 1개와 추가/편집 화면 1개, 총 2개 화면이다.

1. **대시보드 (홈)**
    - 상단 요약: 오늘 날짜, "오늘 할 일 N개 (밀린 일 M개 포함)" (N은 밀린 일 포함 개수, M이 0이면 괄호 부분은 뺀다)
    - 오늘 할 일 영역: 지연(D+n) → 오늘(D-Day) 순으로 카드 나열
    - 그 밖의 집안일 영역: 오늘 할 일 영역에 나온 집안일을 뺀 나머지를 남은 일수가 적은 순(같으면 이름순)으로 카드 나열
    - 카드 구성: 아이콘 · 이름 · 게이지 바 · D-n/D-Day/D+n 배지 · 완료 체크 버튼
    - 우측 하단 "+" 버튼으로 집안일 추가
2. **집안일 추가/편집**
    - 입력: 이름, 주기(일), 마지막 수행일, 아이콘, 메모
    - 편집 모드에서는 삭제 버튼과 수행 이력(P1)을 보여준다

## 7. 알림 및 동기화

폰(Android)은 집 Wi-Fi에 있을 때만 PC 서버와 통신한다. 알림은 기준 시각 이후 폰이 처음 집에 있는 것이 확인될 때, 하루 한 번 보낸다.

**정기 알림 (F7)**

- 발송 시각: 평일 18:00, 주말 10:00 (KST)
- 조건: 기준 시각에 이미 집이면 그 시각에 보낸다. 집에 없으면 그날 23:59까지 집 Wi-Fi에 처음 연결되는 순간 보낸다.
- 내용: "오늘 할 일 N개 (밀린 일 M개 포함)"(M이 0이면 괄호 부분은 뺀다)와 상위 3개 이름. 할 일이 0개면 보내지 않는다.
- 하루 최대 1회. Wi-Fi를 끊었다 다시 연결해도 그날은 다시 보내지 않는다 (Device.lastNotifiedOn으로 판단).

**집 Wi-Fi 판단 방식**: 웹앱은 폰이 연결된 Wi-Fi 이름(SSID)을 읽을 수 없다. 그래서 Android 자동화 앱 MacroDroid(무료)가 도착 신호를 보내는 방식을 기본으로 쓴다.

1. MacroDroid에 "집 Wi-Fi(SSID) 연결 시 → PC 서버 `/api/arrived`로 HTTP 요청" 매크로를 만든다.
2. 서버는 신호를 받으면 세 가지를 확인한다: 기준 시각 이후인가, 오늘 알림을 아직 안 보냈는가, 할 일이 1개 이상인가.
3. 모두 만족하면 웹 푸시(Web Push)로 알림을 보내고 lastNotifiedOn을 오늘로 기록한다.
4. 기준 시각에 이미 집에 있으면 새 연결 이벤트가 없다. 이때는 아래 보완책의 IP 확인으로 기준 시각에 바로 보낸다.

보완책: 기준 시각부터 23:59까지 서버가 5분마다 폰의 고정 IP(공유기 DHCP 예약)가 응답하는지 확인한다. MacroDroid 신호가 빠진 경우를 막고, 그날 알림을 보냈으면 확인을 멈춘다.

보안: `/api/arrived`는 집 네트워크에서 오는 요청만 받는다. MacroDroid 요청에 비밀 토큰을 넣어 다른 기기가 호출하지 못하게 한다.

**오프라인 사용과 동기화 (F8)**

1. 집 밖에서도 앱을 열 수 있다. 마지막으로 받은 데이터를 폰에 저장해 두고 보여준다.
2. 밖에서 한 완료 체크와 편집은 폰의 대기열에 쌓인다. 게이지는 폰에서 즉시 다시 채워진다.
3. 폰이 집 Wi-Fi에서 서버에 닿으면 대기열을 올리고 최신 데이터를 받는다. 앱을 열 때와 연결이 복구될 때 실행한다.
4. 화면 상단에 동기화 상태를 표시한다 (예: "마지막 동기화 10/12 18:03 · 대기 2건").

충돌 규칙:

- 완료 기록은 추가만 되므로 합치기만 하면 된다. 마지막 수행일은 완료 기록 중 가장 늦은 날짜다.
- 집안일 편집(이름, 주기 등)은 updatedAt이 더 늦은 쪽이 이긴다.

**전제 조건**: 웹 푸시와 오프라인 실행(서비스 워커)은 HTTPS에서만 동작한다. 로컬 서버도 mkcert 등으로 인증서를 만들고 폰에 한 번 설치해야 한다. Android에서는 Chrome으로 웹 푸시를 받을 수 있으며, 홈 화면에 설치(PWA)해 앱처럼 쓴다. Chrome 알림 권한과 배터리 최적화 예외 설정을 확인한다.

## 8. 비기능 요구사항 · 범위 · 미결 사항

**비기능 요구사항**

- 모바일 화면에서 우선 사용할 수 있도록 반응형으로 만든다.
- 날짜 계산은 기기의 로컬 시간대(KST) 자정 기준이다.
- 데이터는 앱을 닫아도 유지되어야 한다.
- 대시보드는 집안일 50개까지 1초 안에 표시한다.

**MVP 범위 외 (향후)**

- 캘린더 연동 알림
- 가족 구성원 공유 및 담당자 지정
- 방/공간별 분류, 태그
- 요일 고정형 주기("매주 토요일")
- 완료 통계, 스트릭
- AI 기반 주기 추천 (AIFred라는 이름과 연결되는 확장 후보)

**결정 사항 (모두 확정)**

- 플랫폼: PC에서 로컬 서버로 운영하는 웹앱(PWA). 스마트폰은 브라우저/홈 화면 아이콘으로 접속한다.
- 데이터 저장: PC 서버의 파일 DB(SQLite)가 원본이다. 폰은 사본을 들고 다니며 집 Wi-Fi에서만 동기화한다(7장). 외부 접속(Tailscale)은 쓰지 않는다.
- 일찍 완료해도 예정일을 완료일 기준으로 다시 잡는다.
- "곧 할 일" 기준: 예정일 1일 전(D-1)부터.
- 폰 기종: Android.
- 알림 시각에 집에 없으면: 귀가해 집 Wi-Fi에 처음 연결될 때 보낸다. 재연결해도 하루 1회만.

## 9. 기술 스택

서버는 Python(FastAPI), 화면은 React PWA로 만든다. 서버와 화면은 PC 하나에서 HTTPS로 함께 제공한다.

| 영역 | 선택 | 역할 |
| --- | --- | --- |
| 서버 | Python + FastAPI + Uvicorn | API, 화면 파일 제공, HTTPS(mkcert 인증서) |
| DB | SQLite + SQLModel | Chore, Completion, Device 저장. 파일 하나로 OneDrive 백업 |
| 스케줄러 | APScheduler | 평일 18:00 / 주말 10:00 기준 시각, 5분 간격 IP 확인 |
| 푸시 알림 | pywebpush (VAPID) | Chrome(Android)으로 웹 푸시 발송 |
| 화면 | React + TypeScript + Vite | 대시보드, 추가/편집 화면 |
| PWA / 오프라인 | vite-plugin-pwa | 홈 화면 설치, 서비스 워커, 푸시 수신 |
| 폰 로컬 저장 | Dexie (IndexedDB) | 데이터 사본과 동기화 대기열 |
| 귀가 신호 | MacroDroid | 집 Wi-Fi 연결 시 `/api/arrived` 호출 |
| 상시 실행 | Windows 작업 스케줄러 | PC 로그인 시 서버 자동 실행 |

상태 계산(남은 일수, 게이지, D+n)은 화면(TypeScript)에서 하고, 서버(Python)는 알림에 필요한 "오늘 할 일/밀린 일 개수"만 계산한다. 두 곳의 계산이 어긋나지 않도록 4장 예시를 양쪽 테스트 케이스로 공유한다.
